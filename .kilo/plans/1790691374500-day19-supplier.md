## Scope

### 1. Backend — Supplier Stats & History
- [ ] `GET /api/v1/purchases/suppliers/{supplier_id}/stats` — response: `purchase_count`, `total_spend`, `avg_order_cost`, `unpaid_balance`, `last_purchase_date` (pola agregasi mengikuti `/purchases/payables`; guard `verify_license`; 404 bila supplier tidak ada)
- [ ] `GET /api/v1/purchases/suppliers/{supplier_id}/purchases` — riwayat purchase per supplier (reuse `PurchaseResponse`, order by `purchase_date` desc, filter `payment_status` opsional)
- [ ] Skema Pydantic: `SupplierStatsResponse` di `purchase_schema.py` (bukan dict mentah)
- [ ] Validasi: `payment_terms_days` boleh 0 (Cash) — jangan di-blok; `phone_whatsapp` nullable, tidak perlu regex ketat (YAGNI)

### 2. Frontend — Suppliers Page + Drawer
- [ ] `frontend/src/components/purchases/Suppliers.tsx` — tabel: nama, WhatsApp, terms (`is_credit` badge Cash/Tempo), total spend, unpaid balance, last purchase; search input filter client-side; tombol edit/delete
- [ ] `frontend/src/components/purchases/SupplierDrawer.tsx` — slide-over create/edit: `name` (required), `phone_whatsapp`, `payment_terms_days` (0/7/14/30 chips atau number input); pola mengikuti `IngredientDrawer`
- [ ] Route/menu entry di navigasi Layout (item "Supplier")
- [ ] `api.ts`: tambah section `suppliers.stats(id)` + `suppliers.history(id)` (list/create/update/delete sudah ada)
- [ ] Delete: konfirmasi dialog; handle 400 "Cannot delete supplier with existing purchases" sebagai error toast

### 3. WhatsApp Payment Reminder
- [ ] Helper util `frontend/src/utils/whatsapp.ts`: `buildWaLink(phone, message)` → `https://wa.me/<digits>?text=<encodeURIComponent(message)>` (normalisasi: strip non-digit, skip link bila phone kosong)
- [ ] Integrasi di `AccountsPayableAlert.tsx`: tombol "Ingatkan" per alert (hanya bila `days_until_due <= 3`) — pesan berisi nama supplier, total unpaid, due date, referensi outlet LEUIT
- [ ] Integrasi di detail `SupplierDrawer`/`Suppliers`: tombol kirim WhatsApp (prefill profil supplier)
- [ ] YAGNI: belum perlu WhatsApp Business API / kirim otomatis — cukup deep-link `wa.me` yang membuka WhatsApp client

### 4. Tests
- [ ] Backend target: 8 test — `SupplierStatsResponse` shape; stats aggregation (mock db); 404 supplier tidak ada; history endpoint struktur + order; router `/purchases/suppliers` tetap hijau; delete-with-purchases tetap 400

## Acceptance Criteria

1. Halaman Supplier bisa dibuka dari menu, menampilkan semua supplier dengan statistik ringkas.
2. Supplier baru bisa dibuat/diedit/dihapus via drawer; hapus gagal dengan pesan jelas bila supplier punya riwayat purchase.
3. `GET /suppliers/{id}/stats` mengembalikan agregat yang konsisten dengan jumlah purchase supplier tersebut.
4. Tombol pengingat WhatsApp membuka `wa.me` dengan pesan ter-encode yang berisi detail tagihan; tidak muncul bila nomor kosong atau jatuh tempo >3 hari (untuk AP alert).
5. Semua test baru + existing hijau; lint/typecheck bersih; CI hijau.

## Architecture Notes

- **API pattern:** endpoint stats/history di bawah prefix `/purchases/suppliers/...` (konsisten dengan CRUD eksisting), guard `verify_license`, response Pydantic seperti endpoint lain.
- **Frontend pattern:** komponen presentasi + react-query + zustand bila perlu; slide-over drawer mengikuti `IngredientDrawer`; test mock `@/services/api` mengikuti konvensi test eksisting.
- **Data integrity:** jangan hapus supplier bila ada purchase (RESTRICT di FK sudah ada; endpoint sudah guard 400 — pertahankan).
- **YAGNI:** belum perlu supplier rating engine, PO workflow, multi-kontak per supplier, price-histori chart, WhatsApp auto-blast, atau filter supplier per outlet (Day 16 `outlet_id` boleh menyusul bila purchase di-scoping per outlet).
- **Scope-out eksplisit:** DashboardBuilder/ReportScheduler UI (Day 18 plan) tidak ikut ke Day 19 — fokus supplier penuh.
