# Day 24 Plan: Internationalization (i18n)

**Focus:** Multi-bahasa (id-ID default, en) untuk LEUIT desktop app
**Predecessor:** Day 23 Accessibility Audit (PR #24)

---

## Goals

1. Fondasi i18n: library ringan + resource structure
2. Bahasa default: `id-ID` (sesuai domain F&B Indonesia), opsi `en`
3. String kunci UI terjemah: Layout, Sidebar, Header, modal, tombol
4. Number/date/currency formatting per locale
5. Test coverage untuk i18n utilities

---

## Tasks

### 1. Library & Setup
- Evaluasi opsi tanpa dependency: custom `t()` + JSON resource (YAGNI-friendly) vs `react-i18next`
- Rekomendasi awal: `react-i18next` + `i18next` (standar, lazy load resource, fallbackLng)
- Init: `frontend/src/i18n/index.ts`, `frontend/src/i18n/locales/id.json`, `en.json`
- Wire di `main.tsx`, `lang` attribute di `index.html` update saat ganti bahasa

### 2. State & UI Switcher
- Persist locale di `localStorage` key `leuit.locale`
- Language switcher di Header (dropdown: Indonesia / English)
- Hook: `useTranslation()` komponen konsumsi `t('key')`

### 3. String Migration (batch 1)
- `Sidebar.tsx` (menu labels)
- `Header.tsx` (page title)
- `SkipNav.tsx`, `AccessibleModal.tsx` (close label)
- Auth: unlock modal, error messages
- Resource key namespace: `common.*`, `nav.*`, `auth.*`, `modal.*`

### 4. Formatting
- `frontend/src/utils/i18nFormat.ts`
- Currency: `Intl.NumberFormat('id-ID', { style: 'currency', currency: 'IDR' })` — fallback en USD/IDR sesuai locale
- Dates: `Intl.DateTimeFormat(locale, ...)` — cek `DateRangePicker`
- Angka: grouping/decimal per locale

### 5. Backend Considerations
- Likely none — API returns data, bukan user-facing copy
- Jika error message backend masuk UI: mapping code → teks di frontend

### 6. Tests
- i18n init: default locale id, fallback key behavior
- `t()` returns id vs en
- formatting util: currency/date snapshot id-ID
- Language switcher: persist + re-render
- Target: ≥ 8 test baru
- Regression: typecheck 0 errors, pnpm test pass, CI green
