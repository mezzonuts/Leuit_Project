# Day 16 — Multi-Outlet

**Proyek:** LEUIT
**Status:** 📋 Planned
**Depends on:** Day 15 ✅ (Advanced Forecasting, PR #16)

---

## Goal

Mendukung operasi multi-outlet: setiap outlet punya inventori sendiri, laporan dapat per-outlet maupun konsolidasi, dan user dapat berpindah outlet lewat UI.

---

## Scope

### 1. Outlet Model (Backend)
- [ ] Tabel `outlets`: `id`, `name`, `code`, `location`, `is_active`, `created_at`
- [ ] Tabel pivot `outlet_inventory` atau penambahan kolom `outlet_id` pada tabel inventori (pilih skema paling sesuai arsitektur — local-first SQLite, hindari migrasi berat)
- [ ] Data seeding: 1 outlet default ("Outlet Utama") agar aplikasi lama tetap jalan tanpa breaking change
- [ ] `outlet_id` nullable di lapisan lama → backward compatible

### 2. Per-Outlet Inventory (Backend)
- [ ] Semua query inventori, stock opname, dan restock sheet difilter per `outlet_id`
- [ ] API: `GET /inventory?outlet_id=`, `GET /forecast/restock-sheet?outlet_id=`
- [ ] Validasi: `outlet_id` wajib ada di sistem, error 404 bila tidak dikenal
- [ ] Forecast (Day 15) tetap per-bahan; pastikan data historis konsumsi terisolasi per outlet

### 3. Consolidated Reports (Backend)
- [ ] Endpoint laporan konsolidasi: gabung semua outlet aktif
- [ ] Perbandingan per outlet: valuation, critical alerts, stock health
- [ ] Skema response baru di `schemas/` konsisten gaya `forecast_schema.py`
- [ ] Test: filter per outlet, konsolidasi multi outlet, outlet nonaktif dikecualikan

### 4. Outlet Switcher UI (Frontend)
- [ ] Komponen `OutletSwitcher` di header/sidebar (dropdown outlet aktif)
- [ ] State global (context/store) `currentOutletId`, persist di localStorage
- [ ] Semua halaman (Inventory, Dashboard, Purchases, Forecast) membaca `currentOutletId`
- [ ] Halaman konsolidasi (opsional): tampil semua outlet bila mode "Semua Outlet"
- [ ] Testing: render, switching, persistence, query params ikut outlet

### 5. Tests & Quality
- [ ] Backend: unit test model outlet, API filter, konsolidasi
- [ ] Frontend: test OutletSwitcher + integration per halaman
- [ ] `ruff check` + `mypy` bersih; `pytest` hijau; frontend `tsc` + test hijau
- [ ] CI hijau sebelum merge

---

## Acceptance Criteria

1. Satu outlet bisa dibuat, diaktifkan/dinonaktifkan, dan dipakai penuh di UI.
2. Inventory, restock sheet, dan forecast memakai data outlet yang dipilih.
3. Laporan konsolidasi menampilkan semua outlet aktif dengan benar.
4. Outlet switcher mengubah seluruh data di aplikasi tanpa reload penuh.
5. Aplikasi versi lama (tanpa pilih outlet) tetap jalan dengan outlet default.
6. Semua test baru + existing hijau; lint/typecheck bersih.

---

## Architecture Notes

- **Local-first:** data outlet disimpan di SQLite lokal, bukan cloud multi-tenant.
- **Skema:** pilih jalur paling kecil diff — tambah `outlet_id` dengan default `1` bila mengubah tabel lama terlalu berisiko; fallback ke tabel relasi baru.
- **API:** pola query param `outlet_id` konsisten dengan endpoint forecast Day 15.
- **UI:** pattern switcher mengikuti konvensi komponen frontend yang ada (Layout, drawer, test dengan pattern yang sama seperti PR #7–#12).
- **YAGNI:** belum perlu role/permission per outlet, belum perlu outlet hierarchy (cabang induk/anak).
