# Day 25 Plan: Plugin System & Extensibility

## Objective
Design and implement a plugin architecture that allows third-party extensions for LEUIT without modifying core code. Enable custom integrations, reports, and workflow automation.

---

## Scope

### In Scope
- Plugin manifest schema (JSON/YAML)
- Plugin loader & registry (backend + frontend)
- Sandbox execution environment (WASM/isolated VM)
- Core plugin APIs: hooks, events, UI extensions, data access
- Example plugins: WhatsApp Notifier, Google Sheets Export, Custom Report Builder
- Plugin marketplace UI (admin panel)
- Security: signature verification, permission system

### Out of Scope
- Full plugin marketplace backend (hosting, payments)
- Hot-reload for plugins in production binary
- Cross-plugin dependency resolution

---

## Technical Design

### 1. Plugin Manifest (`plugin.json`)
```json
{
  "id": "com.example.whatsapp-notifier",
  "name": "WhatsApp Notifier",
  "version": "1.0.0",
  "description": "Send low-stock alerts via WhatsApp",
  "author": "Example Corp",
  "license": "MIT",
  "entryPoint": "dist/index.js",
  "permissions": ["inventory.read", "notifications.send", "external.network"],
  "hooks": ["inventory.lowStock", "purchase.orderCreated"],
  "uiExtensions": [
    { "point": "header.actions", "component": "WhatsAppSettings" },
    { "point": "inventory.rowActions", "component": "SendAlertButton" }
  ],
  "configSchema": {
    "type": "object",
    "properties": {
      "apiKey": { "type": "string", "format": "password" },
      "phoneNumbers": { "type": "array", "items": { "type": "string" } }
    },
    "required": ["apiKey", "phoneNumbers"]
  }
}
```

### 2. Backend Plugin Loader (`backend/app/plugins/`)
```
app/plugins/
├── __init__.py
├── loader.py           # Plugin discovery, validation, loading
├── registry.py         # PluginRegistry: get, list, enable, disable
├── sandbox.py          # WASM/Subprocess isolation
├── permissions.py      # Permission checking, capability tokens
├── manifest.py         # Pydantic models for plugin.json
└── hooks.py            # Hook registration & execution
```

### 3. Frontend Plugin System (`frontend/src/plugins/`)
```
src/plugins/
├── index.ts            # PluginManager: load, unload, getExtensions
├── types.ts            # PluginManifest, HookContext, UIExtensionPoint
├── registry.ts         # Extension registry (React context)
├── sandbox.ts          # iframe/WASM sandbox for UI extensions
└── hooks.ts            # usePluginHook, useExtensionPoint
```

### 4. Hook System
```typescript
// Core hooks (backend emits, plugins subscribe)
type CoreHooks = 
  | 'inventory.lowStock'
  | 'inventory.stockChanged'
  | 'purchase.orderCreated'
  | 'purchase.orderReceived'
  | 'pos.syncCompleted'
  | 'forecast.generated'
  | 'audit.logCreated';

// Plugin defines handler
interface HookHandler {
  hook: CoreHooks;
  handler: (context: HookContext) => Promise<void>;
  priority?: number; // execution order
}
```

### 5. UI Extension Points
| Extension Point | Context | Use Case |
|-----------------|---------|----------|
| `header.actions` | `{ user, outlet }` | Add buttons to header |
| `sidebar.sections` | `{ outlet }` | Add nav sections |
| `dashboard.widgets` | `{ outlet, dateRange }` | Custom dashboard widgets |
| `inventory.rowActions` | `{ item, outlet }` | Per-row action buttons |
| `purchase.formFields` | `{ supplier, outlet }` | Extra form fields |
| `settings.tabs` | `{ outlet }` | Settings panels |

### 6. Security Model
- **Signature verification**: Ed25519 signed manifests, verified at load time
- **Permission system**: Capability-based (no ambient authority)
- **Sandbox**: WASM (wasmtime) for backend, iframe + CSP for frontend
- **Resource limits**: CPU time, memory, network allowlist per plugin
- **Audit logging**: All plugin actions logged to audit trail

## Database Changes

```sql
-- plugins table
CREATE TABLE plugins (
  id VARCHAR(255) PRIMARY KEY,           -- plugin manifest id
  name VARCHAR(255) NOT NULL,
  version VARCHAR(50) NOT NULL,
  manifest JSONB NOT NULL,               -- full manifest
  config JSONB DEFAULT '{}',             -- user config
  enabled BOOLEAN DEFAULT false,
  signature BYTEA NOT NULL,              -- Ed25519 signature
  public_key BYTEA NOT NULL,             -- author public key
  installed_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- plugin_hooks table (for debugging/audit)
CREATE TABLE plugin_hooks (
  id BIGSERIAL PRIMARY KEY,
  plugin_id VARCHAR(255) REFERENCES plugins(id),
  hook_name VARCHAR(100) NOT NULL,
  executed_at TIMESTAMP DEFAULT NOW(),
  duration_ms INTEGER,
  success BOOLEAN,
  error TEXT
);
```

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| WASM sandbox complexity | Start with subprocess isolation, migrate to WASM later |
| Plugin conflicts (same hook) | Priority system, explicit conflict detection at load |
| Malicious plugins | Signature verification + permission system + audit log |
| Version incompatibility | Semantic versioning in manifest, compatibility matrix |
