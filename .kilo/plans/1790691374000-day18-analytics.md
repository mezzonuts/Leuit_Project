# Day 18 — Advanced Analytics

**Proyek:** LEUIT
**Status:** 📋 Planned
**Depends on:** Day 17 ✅ (Mobile Companion PWA, PR #18)

---

## Goal

Analytics lanjutan: drill-down report (klik chart → detail), export terjadwal (PDF/Excel via email), custom dashboard drag-drop dengan layout per user, dan date-range picker dengan preset.

---

## Scope

### 1. Drill-down Reports
- [ ] Klik bar/point chart → view detail periode (daily/weekly/monthly)
- [ ] Backend endpoint detail: agregasi per hari/minggu/bulan untuk revenue, purchases, valuation (reuse pola `GET /api/v1/reports/consolidated`)
- [ ] Frontend: navigasi drill-down dari `UsageTrendBarChart` / `ValuationMetricCard` ke detail view
- [ ] Filter `outlet_id` konsisten dengan Day 16

### 2. Export Scheduling
- [ ] `backend/app/services/report_scheduler.py`: job harian/mingguan generate PDF/Excel
- [ ] Endpoint `GET/POST /api/v1/exports/schedule` (list/create), guard `verify_license`
- [ ] Email delivery via SMTP config (env-based); fallback: tulis file ke `exports/` bila SMTP tidak dikonfigurasi
- [ ] YAGNI: belum perlu cron cloud — pakai scheduler in-process / APScheduler bila sudah ada dependensi, atau polling loop sederhana

### 3. Custom Dashboards
- [ ] Frontend `DashboardBuilder.tsx`: grid widget drag-drop (reorder), widget: valuation, sales trend, critical alerts, stock health, forecast
- [ ] Layout tersimpan per user di backend (`dashboard_layouts` JSON) atau localStorage bila single-user
- [ ] `ReportScheduler.tsx`: UI daftar schedule export, toggle aktif/nonaktif

### 4. Date Range Picker
- [ ] Komponen `DateRangePicker.tsx`: preset 7d / 30d / 90d / custom (start-end)
- [ ] Dipakai konsisten di dashboard, reports, dan forecast view
- [ ] Terima param `days` (polos) atau `start_date`/`end_date` — backend harus menerima keduanya

### 5. Tests
- [ ] Backend target: 15 test — report scheduler service, export endpoints, drill-down aggregation, layout model/schema
- [ ] Frontend target: 10 test — DateRangePicker presets, DashboardBuilder reorder, ReportScheduler states
- [ ] `pnpm typecheck` + `pnpm test` + `uv run pytest` hijau; lint 0 error
- [ ] CI hijau sebelum merge

---

## Acceptance Criteria

1. Klik chart membuka detail periode (daily/weekly/monthly) dengan angka konsisten dengan agregasi dashboard.
2. Schedule export bisa dibuat/diaktifkan; job menghasilkan file PDF/Excel (atau email) untuk periode terjadwal.
3. Dashboard bisa diatur ulang widget-nya; layout bertahan setelah reload.
4. Date range picker punya preset 7d/30d/90d dan mode custom; berlaku di semua view analytics.
5. Semua test baru + existing hijau; lint/typecheck bersih; CI hijau.

---

## Architecture Notes

- **API pattern:** endpoint baru ikut prefix `/api/v1/*` + guard `verify_license`, response shape dict konsisten `data`/`summary`/`generated_at` seperti Day 16.
- **Offline/PWA:** pastikan endpoint analytics tetap network-first; export file jangan di-cache SW (endpoint download — pakai `Content-Disposition`, method GET dengan query unik).
- **Scheduler:** hindari dependensi berat; bila APScheduler belum ada di `pyproject.toml`, pakai thread loop sederhana yang di-start dari `main.py` (Day 13 launcher) dengan flag enable/disable.
- **YAGNI:** belum perlu role-based dashboard sharing, belum perlu template email fancy, belum perlu BI-style ad-hoc query builder.
