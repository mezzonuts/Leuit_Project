**Proyek:** LEUIT
**Status:** 📋 Planned

## Goal

Lapisan audit trail immutable: append-only log dengan hash chaining (SHA256 per baris), export compliance (CSV/JSON) yang bisa diverifikasi, dan endpoint deteksi tampering. Fokus integritas data & compliance — bukan UI audit penuh.

## Scope

### 1. Backend — Append-Only Log Table + Hash Chaining
- [ ] Model baru `backend/app/models/audit_log.py`: `AuditLog` — `id`, `timestamp`, `user_id` (nullable, role-based bila user None), `action` (String 100), `entity` (String 255), `before` (Text nullable), `after` (Text nullable), `prev_hash` (String 64), `hash` (String 64)
- [ ] `backend/app/services/audit_trail.py`: `record_audit_log(db, action, entity, before, after, user_id=None)` — ambil `prev_hash` dari baris terakhir (ORDER BY id DESC), `hash = SHA256(prev_hash + canonical(current_data))`, insert **append-only** (tanpa update/delete helper)
- [ ] Canonical string deterministik (JSON sorted-keys) sebelum hash — stabil lintas run
- [ ] Guard `verify_license` konsisten endpoint lain; audit writes dari dalam proses aplikasi (bukan endpoint publik)
- [ ] YAGNI: belum perlu table partition, belum perlu retention job, belum perlu encrypt isi log

### 2. Backend — Compliance Export
- [ ] `GET /api/v1/audit/export?format=csv|json` — stream semua `AuditLog` (atau filter `action`/`date_from`/`date_to` bila murah)
- [ ] CSV: header `id,timestamp,user_id,action,entity,before,after,prev_hash,hash`; JSON: array of `to_dict()`
- [ ] Setiap baris export menyertakan `hash` agar bisa diverifikasi ulang di sisi penerima
- [ ] Guard `verify_license` (export = data sensitif operasional)

### 3. Backend — Tamper Detection
- [ ] `GET /api/v1/audit/verify` — walk chain dari baris pertama: hitung ulang `hash` tiap baris, bandingkan `prev_hash` baris berikutnya; response `{valid: bool, checked: int, broken_at: id|null, reason}`
- [ ] Chain genesis: baris pertama `prev_hash = ""` (atau `"0"*64` — keputusan eksplisit, catat di PR)
- [ ] 404/empty: `{valid: true, checked: 0}` bila belum ada log
- [ ] Skema Pydantic di `backend/app/schemas/audit_schema.py` (atau extend bila lebih pendek): `AuditLogResponse`, `AuditExportResponse`/row, `AuditVerifyResponse`

### 4. Frontend — Audit Trail UI (minimal)
- [ ] `frontend/src/components/audit/AuditTrailTable.tsx` — tabel log (timestamp, action, entity, actor); react-query `GET /api/v1/audit/logs` (endpoint list — buka bila dibutuhkan; minimal export+verify dulu, list endpoint boleh reuse export JSON)
- [ ] `AuditTrailPage.tsx` — header "Audit Trail", tombol "Export CSV" (`window.open`/download) + "Verifikasi Integritas" → tampilkan hasil `verify` (badge hijau/merah + `broken_at`)
- [ ] Route/menu entry: item "Audit Trail" di Sidebar Layout (ikuti pola navigasi eksisting)
- [ ] Reuse `formatRupiah`/date helper `formatters.ts` untuk timestamp
- [ ] YAGNI: belum perlu UI diff before/after per baris, belum perlu filter builder kompleks, belum perlu email notifikasi tampering

## Acceptance Criteria

1. Setiap akses log tercatat append-only: tidak ada helper update/delete di service.
2. `hash = SHA256(prev_hash + canonical_data)` per baris; chain terverifikasi dari genesis sampai baris terakhir.
3. Manipulasi isi baris mana pun (via SQL manual) terdeteksi `GET /audit/verify` → `valid=false` + `broken_at` id baris.
4. Export CSV/JSON menyertakan `hash` + `prev_hash` tiap baris — penerima bisa verifikasi offline.
5. Semua test baru + existing hijau; lint/typecheck bersih; CI hijau.

## Architecture Notes

- **API pattern:** prefix `/audit` + guard `verify_license` (konsisten endpoint operasional lain); response Pydantic seperti endpoint lain.
- **Local-first:** chain hash dihitung lokal di SQLite — verifikasi tanpa internet; export file CSV/JSON portable.
- **Security:** canonical JSON deterministik (sorted keys, tanpa float drift — serialize number stabil); hash pakai `hashlib.sha256` stdlib; SQLCipher sudah cover at-rest encryption — hash chain melindungi **integritas**, bukan kerahasiaan.
- **Reuse:** `OperationalAuditLog` tetap dipakai untuk log operasional ringan (purchase/recipe); `AuditLog` baru khusus trail immutable — **jangan merge dua konsep** (alasan: `OperationalAuditLog` tanpa hash, banyak writer lama).
- **YAGNI:** belum perlu Merkle tree, belum perlu notarization eksternal, belum perlu WORM storage, belum perlu real-time websocket audit feed.
- **Scope-out eksplisit:** mounting `MenuQRPage`/`PublicMenuPage`/`ReceiptView` (gap Day 20) tidak ikut Day 21 — fokus audit trail.
